# 119 / 응급 연계 정책 (초안)

## 1. 핵심 원칙

> **회사는 어떠한 경우에도 119 또는 응급기관에 직접 신고하지 않는다.**
> 응급 신고 결정권은 **보호자 또는 어르신 본인**에게 있으며, 실제 응급 대응 판단의 주체는 보호자·실제 긴급 체계(119 등)이다.
>
> 회사 시스템(AI·규칙 엔진 포함)은 어르신의 발화에 응급 가능성이 있다고 판단되는 경우 **보호자에게 즉시 확인을 요청**할 뿐, 응급 상황을 *확정*하거나 *직접 대응*하지 않는다.

이유:
- 의료법/응급의료법상 직접 신고 권한은 본인·가족·의료기관·구급기관 등 법령상 주체에게 있다(상세 해석은 법무 검토 필요).
- 오인 신고 시 보호자 책임 + 사회적 자원 낭비 가능성
- 통화 기반 정보만으로는 위치/상태 정확성에 한계가 있음

## 2. 시스템 동작

| 상황 | 시스템 동작 |
|---|---|
| ESCALATE 키워드 감지 | `critical` 알림 즉시 발송 (§ 05) |
| 통화 중 "119 불러줘" | AI는 "지금 자녀 분께 바로 알려드릴게요" 발화 후 종료, critical 알림 |
| 보호자가 "119" 액션 클릭 | 보호자가 직접 신고했음을 기록 (`dispatched_119`), 신고 자체는 회사가 안 함 |

## 3. 보호자 안내 문구

critical 알림 카드에는 다음 버튼을 노출:

- "지금 직접 전화하기" → `tel:어르신번호`
- "119에 신고하기" → `tel:119` (보호자 디바이스에서 직접 발신)
- "확인 완료" → `acknowledged` 기록

> 안내 문구: "응급 상황이 의심됩니다. 직접 확인하시거나 119에 신고해 주세요. 회사는 자동 신고하지 않습니다."

## 4. 향후 검토

- 지자체/응급의료센터 협약 시 별도 정책 추가 가능
- 119 안심콜 서비스 연계 검토 (어르신이 사전 등록하는 방식)
