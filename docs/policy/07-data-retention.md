# 데이터 보존 / 파기 정책 (초안)

> 본 표의 모든 보존 기간은 **후보값**이며, 통신비밀보호법·개인정보보호법·전자상거래법·민·형사 분쟁 대응 필요성을 함께 고려해 법무 검토 후 확정한다.
> 자동 cron 작업의 임계값(91일·730일·1095일 등)은 보존 기간 후보값과 1:1 대응되며, 후보값이 바뀌면 함께 조정해야 한다.

## 1. 보존 기간 표 (후보)

| 데이터 | 보존 기간 | 파기 방식 |
|---|---|---|
| 회원 계정 | 탈퇴 시까지 | 탈퇴 + 30일 유예 후 hard delete |
| 어르신 정보 | 보호자 회원 유지 동안 | 보호자 탈퇴 시 함께 파기 |
| 통화 녹음(mp3) | **90일** | Storage lifecycle rule 자동 삭제 |
| 통화 transcript (call_turns) | **2년** | 배치 삭제 (월 1회) |
| 분류 결과 (extracted_check_results) | **2년** | 배치 삭제 |
| 이상징후 / 보호자 액션 | **3년** | 배치 삭제 |
| 약물 카탈로그 | 영구 | 식약처 데이터 갱신 시 버전 누적 |
| 약 복용 기록 | 2년 | 배치 삭제 |
| 음성 동의 녹취 | 동의 유효기간 + 1년 | 동의 만료 후 1년 보관 후 파기 |
| 결제 / 세금 | 5년 | 법정 보존 |
| 접근 로그 | 1년 | 배치 삭제 |
| 백업 | 60일 | rolling backup |

## 2. 회원 탈퇴 처리

```
T+0       : status='pending_deletion', 로그인 차단
T+30d     : hard delete
            - profiles, family_members, care_recipients
            - 관련 call_sessions, call_turns, extracted_check_results
            - 통화 녹음 즉시 삭제
            - voice_consents 즉시 삭제
T+30d+60d : 백업본까지 완전 파기
```

## 3. 부분 삭제 요청

- 보호자가 특정 통화 1건 삭제 요청 가능 (UI 제공)
- 삭제 시 transcript + 녹음 + 추출 결과 + 해당 통화 기반 알림 모두 삭제
- 이상징후 알림이 다른 통화도 근거로 한 경우 → 알림은 유지, 해당 evidence만 제거

## 4. 운영 데이터 분리

- 분류 모델 평가/개선용 데이터셋은 **개인 식별자 제거 + 어르신 동의** 받은 건만 사용
- 외부 모델 학습에 사용 금지
