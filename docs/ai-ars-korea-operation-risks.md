# AI ARS 한국 운영 리스크 메모

> 이 문서는 운영자(파일럿 책임자, CS 담당, PM)가 **AI 안부 전화 서비스를 한국에서 굴릴 때
> 미리 알고 있어야 하는 현실 리스크**를 모은 메모입니다.
> 법률 자문 문서가 아니며, "검토 필요" 항목은 출시 전에 별도로 확인해야 합니다.

---

## 1. 발신번호 표시 / 스팸 차단

- 한국 통신사·단말은 모르는 070·050·국제번호 발신을 자동으로 **"스팸 추정"** 으로 표시하는
  경우가 많습니다. 고령자 단말에서는 아예 무음 차단되기도 합니다.
- Twilio 의 미국 번호로 발신하면 단말에 `+1 ...` 로 뜨고, 자녀라고 알려드린 뒤에도
  부모님이 망설이실 가능성이 큽니다.
- **권장**: 한국 SK브로드밴드/LG U+ 등 국내 발신번호(인증된 050/070, 가능하면 080) 확보.
  파일럿 단계에서는 부모님께 "이 번호로 곁이 전화드릴 거예요" 라고 미리 안내 + 단말 연락처 등록.
- **검토 필요**: 통신사별 발신번호 사전등록(KISA), 070 식별표시 규정.

## 2. 전화 거절 / 무응답이 기본값이라는 현실

- 고령자에게 모르는 번호에서 오는 전화는 받지 않는 것이 안전 기본값입니다.
  첫 1~2회 전화는 거의 받지 않을 가능성을 전제로 운영해야 합니다.
- **운영 정책**:
  - 첫 전화 전에 **보호자가 부모님께 직접 1회 전화로 안내**.
  - 미응답 시 30분 후 재시도 1회 → 그 다음은 SMS fallback 으로 전환 (지금 구현 그대로).
  - "오늘 못 받으셔도 곁은 다시 전화드릴 거예요" 정도의 톤 유지.

## 3. 청취 난이도 / 발화 속도

- 65세 이상은 고주파 청력 저하가 흔합니다. AI 음성이 빠르거나 톤이 높으면 거의 안 들립니다.
- TTS 보이스/속도는 **느리고 낮게** 유지. 한 문장에 정보 1개만.
- 한 번에 두 가지 묻지 말 것 ("식사 하시고 약 드셨어요?" ❌ → "식사는 하셨어요?" → "약은 드셨어요?")
- 첫 인사에 **반드시 자기소개**: "안녕하세요, 자녀분이 신청하신 안부 전화예요, 곁입니다."

## 4. 통화 녹취 / 전사 보관

- 한국에서 **통화 당사자 일방 동의로 녹음 가능**하지만, 보관/전사/제3자 공유는
  별도 동의가 필요합니다.
- 현재 구현은 OpenAI Realtime 의 발화를 turn 단위로 텍스트 저장합니다 (`call_turns.raw_text`).
  음성 파일을 보관하지 않더라도 **텍스트 전사도 개인정보**입니다.
- **운영 정책 권장**:
  - 보호자 가입 시 동의서에 "AI 안부 전화 내용을 보호자가 확인용으로 텍스트로 보관"을 명시.
  - 부모님 첫 전화 첫 문장에 "통화 내용은 가족 확인용으로 기록됩니다" 안내.
  - 보관 기간 정책 (예: 90일) 정하고 자동 삭제 잡 따로 운영.
- **검토 필요**: 개보위 가이드라인, 본인 외 가족(부모님)에 대한 정보 수집 동의 방식.

## 5. 부모님 동의 / 보호자 동의 분리

- 보호자가 "우리 엄마 등록해주세요" 한다고 자동으로 부모님 동의가 생기지 않습니다.
- `voice_consents` 테이블이 있지만 첫 통화 전에 **부모님 본인의 구두/서면 동의** 가
  실제로 받혔는지 운영자가 확인해야 합니다.
- 첫 통화에서 "지금부터 매일 안부 전화 드려도 괜찮으세요?" 라고 묻고, 거부 시 즉시
  `do_not_disturb=true` 또는 `status='paused'` 로 전환.

## 6. 의료행위 오인 방지 (가장 중요)

이 서비스는 **의료기기/의료행위가 아닙니다**. 화면/음성/SMS 어디에도 다음 표현 금지:

- "○○ 의심됩니다", "진단", "응급", "심각합니다", "위험합니다"
- 약물 효과/부작용 판정
- 정신건강 진단 (우울증/치매 의심 등)

대신:

- "확인이 필요합니다"
- "직접 연락해 주세요"
- "반복적으로 확인되지 않았어요"
- "통화에서 이런 표현이 기록됐어요"

룰 엔진(`R004`) 도 "표현이 기록됐어요" 톤으로만 메시지를 만들고 있습니다.
운영자가 이후 카피를 수정할 때 이 톤을 깨면 곧바로 의료행위 오인 리스크가 생깁니다.

## 7. 정신건강 관련 표현 주의

- 부모님이 "죽고 싶다", "사는 게 싫다" 등 자해 암시를 발화한 경우 자동 처리는 위험합니다.
- 현재 코드는 자해 키워드 전용 분기를 두지 않습니다 — **출시 전 검토 필요**.
- 권장 흐름:
  - critical alert 즉시 보호자 SMS,
  - 화면에 자살예방상담전화(1393), 정신건강위기상담전화(1577-0199) **정보 안내만**,
  - **자동 119 신고/외부 기관 통보는 하지 않음**.

## 8. SMS fallback 은 **보조 수단**

- SMS 응답(1/2/3/4) 은 정확도가 음성 통화보다 낮습니다. 오타/숫자 1개만 보내는 경우가 흔합니다.
- 부모님이 SMS 1번 보냈다고 "오늘 정상" 으로 단정하지 말 것.
- dashboard 표기는 "SMS 답장 수신" 정도로만, 음성 통화 성공과 동일한 신뢰도로 표시하지 않습니다.

## 9. 응급 판단은 보호자/실제 긴급체계가 한다

- 시스템은 **신호를 모아 보호자에게 전달**할 뿐입니다.
- critical alert 가 떠도 119/112 자동 연계는 하지 않습니다 (정책상 금지).
- 알림함 하단의 안내 문구를 절대 지우지 말 것:
  > 알림은 진단이 아닌 '재확인이 필요한 신호'입니다.
  > 긴급이라도 자동 119 연계는 하지 않으며, 보호자 판단이 우선합니다.
- 보호자 온보딩 시 "최종 판단은 보호자 본인" 임을 명시적으로 동의받기.

## 10. 비용 / 트래픽 리스크

- 통화 1건 = Twilio 통화비 + OpenAI Realtime 비용. 한 부모님께 하루 1통 기준이라도
  100명만 되어도 매일 100통 + retry. 발신 batch 와 cron 주기를 보수적으로.
- critical alert 가 잘못 폭증하면 SMS 도 동시에 폭증 → 비용/스팸 리포트 리스크.
- **권장**: 운영 초반에는 `cron.job` 의 jobname 에 `-pilot` 붙여 분리, 일일 발신 상한 alert 설정.

## 11. 운영자 액션 정리 (출시 전 체크)

- [ ] 한국 발신번호 확보 + 부모님 단말 연락처 등록 안내 자료
- [ ] 보호자 동의서 / 부모님 동의 절차 문서화
- [ ] 통화 텍스트 보관 기간 / 삭제 정책 결정
- [ ] 자해/응급 표현 발화 시 화면/문구 검토 (1393, 1577-0199 안내)
- [ ] 룰 메시지 카피가 진단형으로 변하지 않았는지 마지막 검수
- [ ] cron 환경 분리 (`-prod` / `-stg` / `-pilot`) + 일일 발신 상한
- [ ] CS 응대 스크립트: "왜 우리 부모님께 전화가 갔나요?" 케이스
- [ ] 보호자 탈퇴/일시정지 요청 시 즉시 `status='paused'` 처리 절차
