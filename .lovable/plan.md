# 커뮤니티 대행업체 DB 서울권 상위 업체로 전면 교체

## 목표
`agencies` 테이블의 31개 레코드를 모두 삭제하고, **8개 카테고리 × 5개 = 40개**의 서울 25개 자치구 소재 인지도 높은 업체로 재구축합니다. 업체는 Google 검색을 통해 실제 운영 중인 곳만 선별합니다.

## 카테고리 (현재 그대로 유지)
1. `hospital` (상급종합/대학병원)
2. `nursing_hospital` (요양병원)
3. `caregiver` (간병 매칭)
4. `cleaning` (청소·가사)
5. `moving` (이사)
6. `funeral` (상조·장례)
7. `hearing_aid` (보청기)
8. `legal_tax` (법률·세무 상담)

## 진행 절차

### 1단계 — 카테고리별 후보 조사
`websearch--web_search` 로 카테고리별 서울 소재 상위 업체를 검색합니다 (예: "서울 간병인 매칭 업체 추천", "서울 보청기 브랜드 본사" 등). 각 결과는 다음 기준으로 필터링:
- 본사·주요 지점이 **서울 25개 자치구** 내에 있을 것 (시립승화원처럼 고양시 소재 시설은 제외)
- 공식 웹사이트가 살아있고 대표번호가 노출될 것
- 인지도/규모가 카테고리 내 상위권일 것

### 2단계 — 검증
선정된 업체 한 곳씩 `code--fetch_website` 또는 `websearch--web_search`로 공식 사이트의 주소·전화번호를 한 번 더 확인하여 데이터 정확성을 보장합니다.

### 3단계 — DB 교체 마이그레이션
하나의 마이그레이션 파일에서 트랜잭션으로 처리:
```sql
DELETE FROM agencies;
INSERT INTO agencies (name, category, sido, sigungu, address, phone, website,
                      tags, verified, source_name, source_url) VALUES
  ...40개 행...;
```
- `sido` = `'서울특별시'`
- `sigungu` = 정확한 자치구명 (예: `'강남구'`)
- `verified = true`, `source_name = '공식 홈페이지'` 또는 `'서울시'`
- `tags`는 카테고리 특성에 맞는 한국어 태그 2개

### 4단계 — UI 확인
교체 후 `/community` 또는 대행업체 카테고리 페이지에 들어가 카테고리별로 5개씩 정상 노출되는지 확인.

## 예상 라인업 (가안 — 1단계 검색으로 최종 확정)

| 카테고리 | 후보 (서울 25개 자치구 한정) |
|---|---|

| nursing_hospital | 보바스기념병원(성동) · 서울시립북부병원(중랑) · 서울시립서북병원(은평) · 힘찬요양병원 강남 · + 1개 추가 조사 |
| caregiver | 케어닥 · 케어네이션 · 한국간병인협회 · 케어유 · 굿네이션 등에서 5개 |

| hearing_aid | 스타키 · 포낙 · 딜라이트 · 시그니아 · 벨톤 등 서울 본점 기준 |

## 메모
- 시립승화원(고양시)·서울추모공원의 분류 일관성: 서울추모공원(서초구 원지동)은 서울시내라 유지, 시립승화원은 제외 후 다른 서울 소재 상조/장례 업체로 대체합니다.
- 기존 31개 행은 모두 사용자 화면 외 참조가 없어 단순 DELETE → INSERT가 안전합니다 (다른 테이블에 외래키 없음).
